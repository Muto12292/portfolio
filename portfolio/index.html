Graviton — Real-Time 2D Physics Engine

Native C++17 Core
C++17 Velocity Verlet Spatial Hash Grid Impulse Collisions Frame Budget Profiling

A real-time gravitational and particle physics engine featuring continuous collision resolution, multi-algorithm numerical integration, and frame time budget telemetry. Built to study numerical stability and phase-space conservation in games.

Physics Pipeline Architecture
Forces (Plummer Gravity) → Symplectic Verlet → Spatial Hash Grid → Narrowphase Collision → Impulse Solver → Renderer
  • Symplectic Integration: Uses Velocity Verlet to maintain stable long-term orbital behavior while keeping Hamiltonian mechanical energy drift bounded ($\Delta E / E_0 < 0.1\%$).
  • Collision & Partitioning: Continuous circle-circle impulse response with restitution. Implementing a Uniform Spatial Hash Grid for broadphase collision culling to scale body capacity from $O(N^2)$ to $O(N)$.
  • Native C++ Core: Standalone C++17 solver benchmarked at 100,000 integration ticks with microsecond throughput (physics_engine.cpp).

TerraGen — Procedural World Engine

Deterministic Generator
Custom Perlin Fractal Brownian Motion 11-Biome Climate Matrix Downhill Gradient Drainage

A deterministic 2D procedural terrain generator built from scratch without external libraries. Features multi-layered fractal noise generation, an 11-biome climate matrix, downhill river drainage, and settlement placement heuristics.

Procedural Generation Pipeline
Seed (mulberry32) → Perlin Noise → fBm Elevation → Thermal Matrix → 11-Biome Synthesis → Gradient Drainage → Settlements
  • Custom Noise Core: Proprietary 2D Perlin noise implementation driven by fractal Brownian motion (fBm) with real-time controls for octaves, lacunarity, and persistence.
  • Ecological Classification: 11-biome matrix correlating elevation, latitude temperature gradients, and moisture distribution (Deep Ocean through Mountain Peaks).
  • Downhill Gradient Drainage: River simulation tracing steepest downhill paths from mountain springs to sea level with coastal settlement heuristics.

Systems Thinking

Engine Architecture & Execution Model

Simulation Loop Design

A game engine's physics loop must guarantee numerical stability and deterministic state advancement regardless of frame rate fluctuations. By separating continuous integration sub-stepping from variable display rendering, systems prevent tunnelling and secular energy drift.

1. Force Accumulation Newtonian Gravitation with Softening
2. Symplectic Integrator Velocity Verlet O(Δt²) Position Update
3. Broadphase Culling Uniform Spatial Hash Grid (O(N) candidate pairs)
4. Narrowphase & Impulse Elastic Contact Resolution & Separation
5. Frame Budget Profiling CPU Time Allocation < 16.6ms Target
Why Physics-First?

Game physics engines are discrete numerical solvers of continuous differential equations. An analytical background in Hamiltonian mechanics, linear algebra, and dynamical systems provides an immediate advantage when diagnosing instability, constraint satisfaction, and collision response.

CORE PRINCIPLE
"Preserve physical invariants first. An integrator that bounds phase-space drift produces believable, stable virtual worlds that never collapse under stress."
